# OCD_ENABLE：过流图像干预编译期摘除（信令保留）

日期：2026-08-28　状态：已与用户对齐（决策 B + A）
关联：`2026-08-27-ocd-pwm-signaling-design.md`（§9 遗留"真过流联调"、§10"ocd 钳位废弃"方向）

## 1. 背景与动机

真过流联调中观察到：出板方波（4053 切出的 1kHz/50% PWM 信令）**时有时无、随机出现**。

归因分析：`ocd.c`（命令级软保护）与 `ocd_sig.c`（信令）共用同一套"连续 peg"判据，但动作互相干扰——`ocd` 跳闸后把 IN 强置 2048 / FB 强置 0（200ms HOLD）→ 振镜回中 → 电流消失、peg 中断 → `ocd_sig` 的 1s 干净释放窗得以累积 → 信令释放（方波消失）→ 盲期结束恢复跟随 → 再次过流……救援循环把持续的过流电气状态搅成间歇，信令随之断续。

用户决策（2026-08-28）：**过流时图像不做任何改变，只发方波。**即摘除 `ocd` 的输出干预，保留 `ocd_sig` 检测+4053 切换信令。这是 2026-08-27 spec §10 预告的"ocd 钳位废弃"方向的落地。

## 3. 改动内容

1. **`ocd.h`**：参数区新增
   ```c
   #define OCD_ENABLE  0U   /* 0=编译期摘除图像干预(过流只发信令不动图像, 2026-08-28);
                               1=恢复 200ms 强置安全值+1s 盲期 */
   ```
2. **`ocd.c`**：全部实现包进 `#if OCD_ENABLE`；`#else` 分支提供 `ocd_init/ocd_state/ocd_trip_count` 空实现（调用点免改，与 `ocd_sig.c` 尾部回退模式一致）。
3. **`main.c`**：`ocd_init()` 调用保留（禁用时为空实现）；挂载处注释更新为当前语义。
4. **`eide.yml`**：文件列表不动（`ocd.c` 照常编译出空实现，规避活动 EIDE 实例回写风险）。

## 4. 运行时语义

- 算法槽链变为 `linear → ocd_sig`（`ocd` 层消失）。过流时 IN/FB 输出原样跟随，**图像零改变**；仅 `ocd_sig` 按轴切 4053 选择脚，把该轴 FB 出口切到常开 PWM 报总控板。
- 管线 ISR 开销减少约 200–300 周期（`AD_DA_BLOCK=32` 下预算裕量进一步加大，系 2026-08-28 冻结修复的额外保险）。
- **预期附带效果**：`ocd` 救援循环消失 ⇒ 真实过流下 peg 持续 ⇒ `ocd_sig` 锁在跳闸态 ⇒ 出板方波应由"时有时无"转为持续。本轮上板的重点观察项。
- 已知不动项（容忍，留待办）：上电瞬间 `ix` 未建立读 0 触发 spurious trip，PB3/PB4 上电高约 1s。

## 5. 默认值与回退

提交态 `OCD_ENABLE=0U`。改 `1U` 重编即完整恢复旧行为（200ms HOLD + 1s 盲期）。

## 6. 验证判据（上板）

1. 启动正常，时间戳数据流持续不中断（冻结修复不回退）；
2. 打圆/扫描出现折返冲轨（ix 读 0000/4095）时，图像**不再被强置中点**；
3. 真过流时出板方波出现，重点确认是否转为持续输出。

## 7. 测试影响

无。宿主单测仅 `tests/ocd_sig`（`ocd_sig.h` 纯状态机），与 `ocd.c` 无涉；`ocd.c` 无宿主单测，宏的两个分支由固件构建覆盖。

## 8. 待办（不阻塞本轮，联调后按需）

- 启动门：上电前 N ms 跳过 peg 检测，消除开机 ~1s 假跳闸高电平；
- `ocd_sig` 释放语义是否需要更"黏"（加长释放窗/锁存），视本轮方波实测决定；
- 架构加固：管线中断降级 + SysTick 提权，预算再穿时丢拍保系统而非整机冻结；
- 恢复 main.c 闪烁循环（现注释中）；`OCD_ENABLE=1` 分支若确认永不再用，物理清理 `ocd.c/ocd.h`。
